# J-PlatPat 验证码助手（Chrome 插件 v0.4.1）

在 J-PlatPat 点「文献単位PDF」后：**自动点确认框的「継続」→ 验证码自动识别并提交 → 自动点「PDFダウンロード」→ PDF 直接存到下载目录**，不再弹出查看器窗口。全程只需要点一下。
识别模型在本地运行，不联网。

## 安装

1. Chrome 打开 `chrome://extensions`，打开右上角「开发者模式」
2. 点「加载已解压的扩展程序」，选择本文件夹
3. 已经打开的 J-PlatPat 标签页要**刷新一次**才会生效

更新插件文件后（包括 `train.bat` 更新了 `model/`），到 `chrome://extensions` 点插件的 🔄 重新加载，再刷新 J-PlatPat 页面。

## 验证码

- 验证码出现 → 本地识别（约 0.2 秒）→ 填入，输入框下方显示「识别 8621 · 置信度 0.87」
- **自动提交**：验证码一出现就识别并提交，不管是点下载、翻页还是打开文献时弹出的。被判错就重新识别再提交，每个对话框最多 3 次；3 次都没过就停下，等你自己看
- 置信度低于 0.7 → 先自动换一张（最多 3 次）；还是没把握就只填入、**不自动提交**，用红字提醒核对
- 你已经自己输入了的不会被覆盖
- 弹窗里显示「用模型的答案提交后，判对 / 判错」的次数和实测准确率

### 什么时候不自动提交

- 弹窗里关掉了「自动提交」
- 置信度不够（见上）
- 正在「自动换图收集」
- 这个对话框已经自动提交满 3 次

插件自己从不点「文献単位PDF」或翻页，整条链路都由你那一下点击开始。

> v0.3 只在“你亲手操作后 15 秒内”弹出的验证码才自动提交。但 PDF 生成慢、从列表点开文献、翻页时，验证码常常超过这个时间才出现，链路会卡在 OK。v0.4 去掉了这个限制。

## PDF 直接下载

J-PlatPat 点「PDFダウンロード」时，会把 PDF 列表写进 `localStorage.p0205Param`，然后用 `window.open('/p0205')` 弹出查看器窗口。
插件的 `page_hook.js` 在页面里拦下这个窗口，把列表里的 PDF 直接交给 Chrome 下载：

- 保存在 `下载目录\J-PlatPat\`
- 文件名按公报号整理：`JPA 2001330771-000000.pdf` → `JP2001-330771A.pdf`；分成多个文件的会加 `_1`、`_2`
- 点「文献単位PDF」后弹出的确认框（「文献単位PDFの出力には、数分かかる場合があります。」）自动点「継続」
- 「PDFダウンロード」出现时自动点，每个按钮只点一次
- 这两步由弹窗里的「自动点「継続」和「PDFダウンロード」」控制
- 关掉「直接下载文件」后，恢复成原来弹查看器窗口的方式

如果 Chrome 设置里开了「下载前询问每个文件的保存位置」，每次仍会弹出保存对话框。

## 切到别的标签页时

Chrome 会给看不见的标签页的计时器降速：切走后最多每秒触发一次，在后台待满 5 分钟后最多每分钟一次。v0.4.1 起，插件的每一步都不再依赖计时器：

- 验证码、「継続」、「PDFダウンロード」一出现就处理。插件监听页面变化和图片加载，不再定时检查
- 前台时点 OK 前会等 0.4～0.7 秒，点「継続」前会等 0.15 秒，好让你看清填了什么。后台时没人看，直接点

J-PlatPat 页面**自己**的计时器插件管不着，比如查询 PDF 是否生成好、对话框开关的动画。如果切到后台后还是卡在某一步，按 F12 → Console 筛选 `[jpp-captcha]` 查看。每条日志都带时间和「前台 / 后台」，能看出卡在哪两步之间：

```
13:30:22.884 后台 发现验证码 …
13:30:22.993 后台 自动提交 5555（第 1 次）
13:30:23.173 后台 验证码通过（5555），对话框已关闭
13:30:23.330 后台 自动点「PDFダウンロード」
```

最稳妥的办法是把 J-PlatPat 放进一个单独的窗口，不要最小化，也不要被别的窗口完全挡住。Chrome 只给看不见的页面降速。另外，Chrome 的「节省内存」「节能模式」可能会冻结或丢弃长时间不用的标签页，可以在设置里把 `j-platpat.inpit.go.jp` 加进「始终保持这些网站处于活动状态」。

## 开发者选项（弹窗底部，默认折叠）

### 收集图片

「保存验证码图片」打开时，会存到 `下载目录\jpp_captcha\`：

| 文件夹 | 含义 | 文件名 |
|---|---|---|
| `ok/` | 验证通过，**文件名开头就是正确答案** | `8621_20261005-183012-123.png` |
| `wrong/` | 提交后换了图（输错），开头是输入值，**不是答案** | `1234_....png` |
| `unlabeled/` | 点了再描画、空提交，或直接关闭 | `20261005-....png` |
| `debug/` | 「导出当前验证码区域 HTML」的输出 | |

判定逻辑（2026-10 实测）：点 OK 后，对话框中的图片会先消失约 0.8 秒；输错时换成新图，没有错误提示；输对时同一张图闪回后对话框关闭。

### 自动换图收集

1. 手动点一次下载，让验证码对话框弹出来
2. 设置目标张数和间隔（最短 1 秒），点「开始自动换图」。插件会定时点「再描画」，每换一张就存一张到 `unlabeled/`；收集期间不识别、不提交
3. 达到目标张数、或连续 3 次换图失败（可能被限流）时自动停止

可以开几个**独立窗口**同时收集，进度由后台统一计数。窗口必须在屏幕上可见：后台标签页或被完全挡住的窗口，Chrome 会大幅降速。

## 文件

| 文件 | 作用 |
|---|---|
| `page_hook.js` | 运行在页面自己的 JS 环境里（`world: MAIN`），拦截 PDF 查看器窗口 |
| `content.js` | 找验证码、识别、填入、自动提交、自动点 PDF 下载、收集图片 |
| `model.js` + `model/` | 纯 JS 推理和模型权重 |
| `background.js` | 下载 PDF、保存图片、统计 |
| `popup.html` / `popup.js` | 设置弹窗 |

## 调试

F12 → Console，筛选 `[jpp-captcha]`，可以看到「模型已加载」「已填入」「自动提交」「自动点 PDFダウンロード」「直接下载 PDF」等日志。
J-PlatPat 改版导致定位不到时，在开发者选项里点「导出当前验证码区域 HTML」，然后修改 `content.js` 顶部的 `CFG` 选择器。
